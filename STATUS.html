1. Project Goal

Build a single-purpose, pipelined, feed-forward ASIC that runs YOLO26n int8 inference end-to-end at "bonkers throughput." Each layer of the network gets its own dedicated dataflow silicon — no shared MAC array, no instruction fetch, no programmability.

2. Architecture at a glance

The chip is a spatial pipeline: every op in the YOLO26n graph — convolution, residual add, concat, upsample, attention, detect head — is its own dedicated block, all resident on-die at once. Activations stream block-to-block; skip connections are buffered in on-die SRAM FIFOs. There is no instruction memory, no scheduler, no shared compute fabric.

3. Why a spatial pipeline (not a shared-MAC engine)

A common reaction to the YOLO26n op graph is: "most of the compute is sequential — convolution depends on convolution. Where's the parallelism, and aren't you just building a giant systolic array?" The answer is no: we exploit a kind of parallelism a shared-MAC / FSM design does not.

The op graph is topologically sequential — but that only constrains latency, not throughput. Once the pipeline is full, every stage is busy every cycle, even though any given pixel still walks through the stages in order — the same trick a CPU pipeline uses to get IPC ≈ 1 from sequential code. At steady state the L0 stem is processing frame N+70 while the detect head finishes frame N: different silicon, working concurrently on different frames. Skip connections become on-die SRAM FIFOs; concat/add nodes become small mux / add_rq blocks wired between stages.

4. The conv_stage datapath (instantiated 102×)

Every convolutional layer is a parameterized instance of conv_stage — the synthesizable per-layer streaming wrapper. It turns a raster int8 activation stream into the next layer's stream, hiding the per-tile dataflow inside. Per-layer constants (channel counts, kernel, stride, parallelism, quantization scales) come from a generated package; weights/scale/bias live in on-die ROMs.

Per-pixel cycles = (COUT / P_COUT) × (CIN / P_CIN); the generator balances these factors per layer to fit the global frame budget. The numerical scheme:

out_i8 = sat_i8( round( fp16(acc_i32) × scale_fp16 + bias_fp16 ) )    [+ optional SiLU LUT, + optional residual add_rq]

8. Risks & open questions

  • Skip-FIFO SRAM bandwidth: P3/P4/P5 skip buffers must absorb burst writes from the backbone and feed slower reads to the neck/head. Sizing is set by the static schedule; bandwidth is assumed adequate but not yet measured.
  • External activation IO: the current model assumes "magical SRAM" — streams in and out without contention. Real IO bandwidth may force T_FRAME down (the per-layer P_PIX/P_COUT/P_CIN knobs re-balance at a slacker budget).
  • Whole-chip verification: all 102 layers in one Verilator design is infeasible (lint of the conv backbone alone is ~80 s / ~8 GB). End-to-end validation must be a block-chained C++/golden flow, not a monolithic elaboration.
  • Detect-head on real images: end-to-end vs ORT is meaningful only on real images with separated detections — on object-free synthetic input the TopK boundary churns and cosine collapses even when the hardware is correct (gated instead on an int8 reference).
